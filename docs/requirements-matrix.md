# Requirements Traceability Matrix

**Status:** Phase 0 traceability baseline.  
**Authority:** `docs/product.md` defines approved `MUST` requirements, recommended `SHOULD` requirements, and unresolved `PROPOSED`/`OPEN` choices. This matrix does not approve unresolved choices.  
**Implementation status verified against:** current `src/`, `tests/`, `package.json`, placeholder routes, and documented architecture.

## Status and test keys

- **Complete:** Implemented and adequately tested for the stated requirement.
- **Partial:** Some real behavior exists, but persistence, security, accessibility, production assets, approval, or required tests are missing.
- **Not Started:** No substantive implementation exists; placeholders, fixtures, and disabled controls do not count.
- **Blocked:** Final implementation requires an unresolved product, policy, provider, or architecture decision.
- **Tests:** `UNIT` unit/component, `DB` migrations/constraints, `RLS` authorization, `INT` integration/worker, `CONC` concurrency/idempotency, `E2E` browser workflow, `SEC` security/privacy, `A11Y` accessibility, `MOB` Android/responsive, `VIS` rendered visual review, `PERF` performance, `UPLOAD` hostile upload/storage, `NOTIF` notification, `MOD` moderation/admin.

## Unresolved requirements and decisions

All `PROPOSED` and `OPEN` items remain unresolved and are consolidated in `docs/decision-register.md`. They must not be treated as matrix requirements until explicitly approved and recorded in `docs/product.md`.

Key unresolved categories are limited to technical or later-policy details: the exact reserved-Username registry; autosave debounce/retry and conflict presentation; handwriting storage placement; the concrete licensed city source/coverage/update cadence; optional “Accept sender”; worker cadence/thresholds/alerting; notification providers; broader retention/moderation/legal policy; visual assets; and operational budgets. Inventory, return and minimum-leg semantics, draft persistence, content limits, privacy modes, no-recall/ineligible-recipient behavior, state separation, idempotency, transcription, sender archive and worker recovery contracts are approved.

## Coverage assessment

- **Adequately covered:** no complete product `MUST` requirement yet has full required coverage.
- **Partial local coverage:** RAV-001/RAV-003 fixture presentation; COMP-001/COMP-002/COMP-003/COMP-004 local composer behavior.
- **Existing tests:** `src/lib/letters/editor.test.ts`, `tests/e2e/composer.spec.ts`, `tests/e2e/navigation.spec.ts`, and `tests/e2e/baseline.spec.ts` cover the local editor, fixture rookery, navigation, responsive shell at 320/360/390/768/1280px, focus/skip navigation, overflow, simulated high text size, reduced motion, accessible names and image metadata.
- **Major gaps:** all database, migration, RLS, storage, authentication, concurrency, dispatch, worker, anti-leak, inbox, relationship, upload, notification and moderation tests; real screen-reader/Android device testing; comprehensive performance, contrast, cross-browser and production visual acceptance tests.

Update this matrix whenever a requirement changes status, moves phase, gains coverage, or is explicitly deferred.
